# NUTMEG-14 (v1.4.0-1.13.2-2) Release Plan

## Overview
The **NUTMEG-14** release will focus on maturing our automated release system from "Reliable Overwrites" to "Principled Provenance." Our goal is to achieve SLSA Build Level 2 alignment by ensuring that every released asset is a mathematically verified promotion of a `main` branch canary.

## Core Objectives

### 1. The Provenance Ledger (SLSA Level 2)
Currently, our release tagger rebuilds code. In `-2`, we will implement the **Build Ledger**.
- **Action:** Update the `main` CI to aggregate all `*.tag` files generated by the Makefiles into a single `PROVENANCE.json`.
- **Content:** This file will record the exact `image:tag@sha256` for all 31+ OCI images.
- **Outcome:** We will have a permanent, version-controlled record of exactly what went into every revision.

### 2. O(1) Tagging & Promotion
We will decouple the "Build" phase from the "Release" phase.
- **Action:** Modify `release-talos-assets.yml` to stop running `make`. Instead, it will read `PROVENANCE.json` and use `crane copy` or `skopeo` to promote the pre-built `main` branch manifests to the release tag.
- **Outcome:** Release builds will drop from ~20 minutes to <60 seconds, and we eliminate the risk of tag-time build failures.

### 3. CI Modularization (Agility)
We will continue removing logic from the fragile YAML workflows.
- **Action:** Create `hack/build-talos.sh` to wrap the complex Makefile and `gen-profiles.sh` invocations.
- **Action:** Move the "Tag Promotion" loop into a standalone script.
- **Outcome:** Full portability. A developer can run the entire "Release Rubric" locally to verify everything is in sync before merging.

### 4. Base Image Security Audit
- **Action:** Use the new Ledger to compare the image layers between `-1` and `-2`.
- **Goal:** Explicitly document which base image CVEs were patched by the mutable tag overwrite, providing a clear "Security Freshness" report in the release notes.

## Success Rubric for -2
- [ ] `main` CI outputs a valid `PROVENANCE.json` artifact.
- [ ] Release tag build finishes in under 2 minutes.
- [ ] Provenance Rubric validates SHA256 digests, not just presence.
- [ ] No YAML-specific logic remains in the "Build" or "Promote" steps.
